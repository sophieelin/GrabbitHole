# Development Plan

## 1. Timeline

| Date | Stage | Expected Deliverables |
|---|---|---|
| Nov 16–19 | Concept Design | Finalize concepts and synchronizations; set up project structure and database. |
| **Nov 23** | **Alpha** | Create shared research projects, add sources and connections, and visualize basic graphs. |
| **Nov 30** | **Beta** | Browser extension and session tracking, preliminary graph review, AI topic grouping, and contribution approval workflow. |
| Dec 7 | User Testing | Test browsing sessions, graph editing, and collaboration; collect feedback and fix major issues. |
| Dec 9 | Final Demo | Polish UI, resolve bugs, and complete documentation. |

## 2. Team Responsibilities

| Member | Responsibility |
|---|---|
| Person 1 | Sessioning, DiscoveryLinking, and browser extension |
| Person 2 | Grouping and Claude integration |
| Person 3 | Contributing and Collaborating |
| Person 4 | Frontend and graph visualization |
| Everyone | Integration, testing, and documentation |

## 3. Key Risks and Fallbacks

| Risk | Mitigation / Fallback |
|---|---|
| Browser extension complexity | Start with basic session tracking; fall back to manual source and connection entry. |
| Graph visualization becomes cluttered | Use an existing graph library; simplify to collapsible topic groups if needed. |
| AI grouping is inaccurate | Allow manual corrections; fall back to manual grouping. |
| Contribution approval and graph merging are difficult | Start with approving entire preliminary graphs; defer individual edit proposals if needed. |
| Limited development time | Prioritize creating projects, recording research paths, and viewing shared graphs. |
